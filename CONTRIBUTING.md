# Contributing to Nithin Thadem's Repository

Thank you for your interest in contributing to this repository! This document provides guidelines and information for contributors.

## Getting Started

### Prerequisites

- A GitHub account
- Basic understanding of Git and GitHub workflows
- Familiarity with the technologies used in this repository

### How to Contribute

#### Reporting Issues

1. Check existing issues to avoid duplicates
2. Use clear and descriptive titles
3. Provide detailed information about the issue
4. Include steps to reproduce if it's a bug
5. Add relevant tags and labels

#### Making Changes

1. **Fork the repository**
   ```bash
   # Fork this repository on GitHub, then clone your fork
   git clone https://github.com/YOUR_USERNAME/Nithin-Thadem.git
   cd Nithin-Thadem
   ```

2. **Create a branch**
   ```bash
   git checkout -b feature/your-feature-name
   # or
   git checkout -b fix/issue-number-description
   ```

3. **Make your changes**
   - Follow existing code style and conventions
   - Add meaningful commit messages
   - Test your changes thoroughly

4. **Commit your changes**
   ```bash
   git add .
   git commit -m "feat: add new feature description"
   # or
   git commit -m "fix: resolve issue #123"
   ```

5. **Push to your fork**
   ```bash
   git push origin feature/your-feature-name
   ```

6. **Create a Pull Request**
   - Provide a clear description of your changes
   - Reference any related issues
   - Include screenshots if applicable
   - Ensure your PR passes any automated checks

## Code Style Guidelines

### General Principles

- Write clean, readable, and maintainable code
- Follow language-specific conventions
- Add comments where necessary to explain complex logic
- Keep functions and methods focused on single responsibilities

### Commit Message Format

Use semantic commit messages:

```
type(scope): description

[optional body]

[optional footer]
```

Types:
- `feat`: New feature
- `fix`: Bug fix
- `docs`: Documentation changes
- `style`: Code style changes (formatting, etc.)
- `refactor`: Code refactoring
- `test`: Adding or updating tests
- `chore`: Maintenance tasks

Examples:
- `feat(profile): add new contact form`
- `fix(readme): correct broken links`
- `docs(contributing): update guidelines`

## Review Process

1. **Initial Review**: Maintainers will review your PR for technical accuracy
2. **Automated Checks**: Ensure all CI/CD checks pass
3. **Community Feedback**: Open to community input and suggestions
4. **Final Approval**: Maintainer approval required for merge
